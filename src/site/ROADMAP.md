# ROADMAP

转变轴：内部工程档案 → 对外公开站。起点是散在 `data/profile` 各产品目录里的档案，终点是外部读者能自己查、自己判的公开站。

阶段按「先能读、再能看、最后能查」排：数据源不通，后面全是静态样页；案例与分析建立在档案已被正确呈现之上；检索与多工程只有在条目量足够时才成立。

## v0.1.0 档案能读、能呈现

**达成标志**：站点页面上的条目与数字来自 `data/profile`，改档案文件页面即变，不依赖手写死页。

**顺序依据**：数据源接入是其余各项的前置——先有读数，才谈呈现。

**代价**：不做，则「公开披露」只是手写介绍页，档案更新不影响站点。

- [ ] 工程档案数据源接入：读 `data/profile` 下各产品目录的 `index.md` 与主题文件
- [ ] 公开披露工程信息：工程概览、工程规范、工程实践三块各有页面，内容与档案文件对应
- [ ] 工程规范展示：章程、标准、工作手册三类各至少一篇渲染完成

## v0.2.0 有案例、有指标

**达成标志**：至少一个真实工程实践案例成页；页面上至少两项指标由档案算出且写出计算口径。

**顺序依据**：案例与指标都以 v0.1.0 的数据通路为前提；无通路时二者只能手写，写完即过时。

**代价**：不做，站点只能陈列目录，外部读者看不出这套工程做得怎么样。

- [ ] 工程实践案例展示：一个案例成页，含背景、做法、结果三段
- [ ] 工程数据分析：给出至少两项从档案算出的指标（如文档数、章节数、规范覆盖条数），并在页面标出口径
- [ ] 移动端适配：375px 宽下首页与两个主页面无横向滚动

## v1.0.0 能查、能扩

**达成标志**：输入关键词能定位到具体档案条目并跳转；同一站点接入第二个工程档案仓。

**顺序依据**：检索依赖条目已成规模，多工程依赖单工程的读法稳定。

**代价**：不做，站点止于单工程橱窗，外部读者无法按需取用。

- [ ] 工程档案检索：关键词命中具体档案条目并跳转
- [ ] 多工程支持：接入第二个工程档案仓，与首个工程在同一站呈现
